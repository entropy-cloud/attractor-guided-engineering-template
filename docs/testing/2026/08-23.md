**Finding (recorded, not fixed — engine-side, out of this plan's zero-engine-diff red line)**: the monitor's step-LOG endpoints are `oc-`-prefix-convention-only — `listStepLogs` matches `^oc-(.+)-(\d+)-([a-z0-9]+)\.log[.prompt]` and `handleGetLog` searches `oc-<step>-` prefixes (monitor.js:461/646), so native-mode log artifacts (`native-<step>-…`) are NOT listed in the run-detail log panel and `GET /api/runs/<id>/logs/<step>` answers `{"error":"log not found"}` for native runs. Run list/detail/steps/markers/timing/config rendering is unaffected (run-state file-format identity holds — R3 §3 group 6's claim). This contradicts the WI7 packaging-doc sentence "preserving monitor log viewing" for the log-endpoint subset; doc corrected by this plan's Phase 3, engine-side regex widening recorded as follow-up (`docs/bugs/2026-08-23-monitor-native-log-naming.md`).
