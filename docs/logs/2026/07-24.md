# Development Log - 2026-07-24

- mission-driver CLI 依赖 vendor 化：`commander@15` 内联进仓库，实现「clone 即跑，无需 `pnpm install`、无构建步骤」。
  - 动机：引擎核心本已零依赖，唯一 npm 依赖是 CLI 层 `commander`。为让协作者 clone 后直接 `node src/main.js`，调研业界实践（vendor / util.parseArgs / bundle / commit node_modules / Yarn PnP），选定 **vendor（供应商内联）**——commander 纯 ESM、零传递依赖、无原生二进制，是 vendor 的理想对象，行为 100% 不变、回归风险最低。
  - 改动：新增 `tools/mission-driver/vendor/commander/`（`index.js` + `lib/` + `LICENSE` + `package.json`，源自 15.0.0）与 `vendor/README.md`（记录来源版本 + revendor 升级步骤）；`src/main.js:5` import 改为 `../vendor/commander/index.js`；`package.json` 移除 `dependencies.commander`；删除 `pnpm-lock.yaml`。因 mission-driver 自身 `"type":"module"`，vendored `.js` 自动按 ESM 解析。
